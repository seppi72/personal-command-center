# Manual entry, not bank aggregation, for Finances

The Command Center's stated goal is aggregating the owner's life data "with minimal manual entry" (see the project description at the top of `CONTEXT.md`), and every other mirrored domain (Calendar, School) follows that by pulling from one external system of record. Finances was scoped the same way at first — evaluated against bank-aggregation APIs (Plaid, SimpleFIN Bridge, Teller.io) as a CalDAV-style pull integration. That was dropped: the owner holds a mix of digital and traditional banks, and no single aggregation API covers all of them, so an aggregation-first design would still need a manual fallback for whatever it couldn't reach — adding integration complexity without actually removing manual entry.

Finances is instead fully owner-logged and canonical (see "Source of truth" in `CONTEXT.md`), the same shape Work Hours already has for the same reason (no single external system of record covers all of it). The trade-off is accepting manual entry as this domain's normal path rather than its fallback — a deliberate exception to the project's aggregation-first default, made because no external source can actually deliver on it here.
