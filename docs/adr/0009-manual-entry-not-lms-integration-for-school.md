# Manual entry, not LMS integration, for School

ADR-0001 named School a mirrored domain alongside Calendar, anticipating an external ingestion job the same shape as Calendar sync (ADR-0002) — `Course`'s own doc comment earmarked this as future ticket #20 scope. In practice there's no accessible school data source to pull from: no LMS API, no exportable feed, nothing to run a `CalendarSyncSchedule`-style recurring pull against. To-dos, quizzes, study time, and class meetings are typed in by hand, the same way Work Hours and Finances are self-logged (ADR-0006).

School is instead canonical, not mirrored (see "Source of truth" in `CONTEXT.md`). Most of it needed no new work at all: a to-do or quiz is already a Task with a Deadline under an owner-created Course (tickets #19/#20), and study time is already a Time Entry attached to a Course (ADR-0004, tickets #27/#28). The one real gap was class meetings — Personal Commitment had no way to reference a Course. It gains a single optional Course link for that (Course-only, not Time Entry's four-way container exclusivity — there was no stated need for Personal Commitment to also attach to a Task/Project/Client), guarded by the same delete-while-referenced protection Time Entry's containers and Finances' Accounts already have (tickets #29, #38). No sync job, external client, or upstream-reconciliation logic gets built for School — there's nothing external to reconcile against.
